# Программный комплекс предиктивного автоматического каскадного регулирования микроклимата (САУ)

Современная кроссплатформенная система автоматического регулирования (САУ) параметрами микроклимата в производственном цеху. Комплекс включает в себя:

- **Физический симулятор (цифровой двойник):** термодинамическая модель первого порядка на базе критериальных уравнений теплообмена (\epsilon-NTU).
- **Каскадный регулятор:** внешний ПИ-контур с защитой от интегрального насыщения (Anti-Windup) и локальные внутренние интегральные контуры регулирования исполнительных механизмов.
- **Интеллектуальная вентиляция:** логика "Fan Boost", плавный разгон (Slew Rate Limit) и запуск по температурному коридору допуска.
- **Конечный автомат (FSM):** безопасный пуск (интерлок вентиляторов), сенсорно-ориентированная динамическая продувка и адаптивный расчет времени предпуска.
- **Веб-интерфейс оператора:** дашборд реального времени с графиками, ручным/автоматическим перехватом и планировщиком смен.

## Физико-математическое обеспечение (Для защиты диплома)

### 1. Нелинейная модель теплообмена (\epsilon-NTU)

Для исключения физических парадоксов теплоотдача ТЭНов калорифера (T_{heater}) и испарителя (T_{cooler}) проходящему воздуху рассчитывается по методу эффективности теплообменных аппаратов:

- Массовый расход воздуха через канал: G = D \cdot F \cdot G_{max} (кг/с).
- Число единиц переноса тепла: \text{NTU} = \frac{K_{active}}{G \cdot c_{air}}.
- Эффективность теплопередачи: \epsilon = 1 - e^{-\text{NTU}} (ограничена физическим пределом [0, \ 1]).
- Температура притока: T_{inflow} = T_{out} + \epsilon \cdot (T_{heater} - T_{out}).
- Активный отвод энергии от оборудования: P_{active\_loss} = G \cdot c_{air} \cdot (T_{inflow} - T_{out}).

Данный подход строго соблюдает закон сохранения энергии: тепло калорифера не исчезает в «черной дыре» при малых оборотах вентилятора, а температура притока нелинейно зависит от скорости воздушного потока.

### 2. Каскадный регулятор и логика "Fan Boost"

- **Anti-Windup:** Интеграл внешнего контура САУ временно прекращает накапливать сумму при достижении физического предела мощности вентиляторов (100\%) или выходе температуры притока за лимиты ТБ (16\text{--}40^\circ\text{C}). Это исключает автоколебания и перерегулирование.
- **Вентиляторный буст:** Вентилятор работает на минимальном экономичном уровне F_{min} = 20\%. Разгон вентиляторов активируется только при уходе абстрактного ПИД-выхода за порог \Delta T_{fan\_trigger} или при возникновении неудовлетворенного температурного дефицита притока.
- **Коридор допуска и Slew Rate Limit:** Для исключения вдувания ледяного уличного воздуха вентиляторы удерживаются на F_{min}, пока приток не прогреется до коридора допуска в 5.0^\circ\text{C} от уставки. Нарастание мощности вентилятора жестко ограничено пределом \Delta F_{step} = \pm 10\% за один такт (2 с) для имитации механической инерции ротора.

### 3. Вероятностный автомат тепловыделений

Внутри симулятора реализован стохастический автомат из N=5 групп оборудования. Вне смены тепловыделение минимально (1\text{ кВт}). При старте смены мгновенно запускаются две группы, а во время смены состояние групп изменяется по вероятностной модели Маркова с ежеминутной оценкой вероятностей включения/выключения (p_{on}=0.02, p_{off}=0.015), обеспечивая естественные тепловые колебания в цеху.

## Инфраструктурные особенности проекта

1. **Потокобезопасность (Event Loop):** Все эндпоинты бэкенда объявлены как асинхронные `async def`. Они выполняются в едином потоке (Event Loop) совместно с асинхронным циклом симуляции, что полностью исключает состояния гонки (race conditions) при чтении/записи глобальных переменных состояния.
2. **Синхронизация часовых поясов:** Инициализация БД, логи и планировщик жестко привязаны к часовому поясу `Europe/Minsk` (ZoneInfo), что гарантирует корректность работы расписания в Docker-контейнерах независимо от системных настроек времени хост-машины (UTC).
3. **Оптимизация БД SQLite:** СУБД SQLite инициализируется с таймаутом разблокировки в 30 секунд и принудительно переводится в режим **WAL (Write-Ahead Logging)**. Это позволяет выполнять фоновую запись телеметрии каждые 2 секунды без блокировки запросов пользователя на изменение смен.

## Системные требования и установка

Для быстрого запуска требуется установленный **Docker Desktop** (запущенный).

### Быстрый старт через Docker (Рекомендуемый способ)

1. Склонируйте репозиторий и перейдите в корень проекта.
2. Соберите и запустите контейнеры: 
  ```bash
  docker compose up --build -d

  ```
3. Проверьте доступность ресурсов:
  - Панель оператора (веб-интерфейс): [http://localhost:3000](http://localhost:3000)
  - REST API бэкенда: [http://localhost:8000/api/status](http://localhost:8000/api/status)
  - Документация API Swagger: [http://localhost:8000/docs](http://localhost:8000/docs)
4. Остановить систему: `docker compose down`.

## Конечный автомат состояний (FSM)

Система автоматически циклирует по пяти состояниям:

- `STANDBY`: заслонки закрыты (D=0), оборудование и вентиляция отключены (0\%). Переходит в активный режим при выходе параметров внутри за аварийные рамки безопасности (<12^\circ\text{C} или >28^\circ\text{C}) или при приближении смены.
- `PRE_START`: предиктивный прогрев/охлаждение цеха к началу смены. Время предпуска вычисляется адаптивно по формуле экспоненциального скользящего среднего тепловой скорости здания.
- `WORK_SHIFT`: активное точное удержание комфортной уставки T_{target} во время смены.
- `SAFETY_CORRECTION`: аварийный прогрев или охлаждение по лимитам ТБ во внерабочее время.
- `PURGING`: динамическая продувка оборудования. Активируется при переходе в STANDBY. Нагреватель и охладитель выключаются, заслонки открываются, вентилятор включается на 30\% для безопасного остывания ТЭНов (ниже 45°C) и осушения испарителя (выше 15°C) перед полным остановом.

## Структура базы данных (`climate.db`)

### Таблица `telemetry_logs` (Логирование каждые 2 секунды)

- `id`: INTEGER (PK, Autoincrement)
- `timestamp`: DATETIME (ZoneInfo: Europe/Minsk)
- `inside_temp`: FLOAT (Фактические показания датчика внутри цеха, с шумом)
- `outside_temp`: FLOAT (Температура на улице, суточные колебания 0..10°C)
- `inflow_temp`: FLOAT (Показания датчика притока воздуха в воздуховоде, с шумом)
- `heater_temp`: FLOAT (Температура поверхности ТЭНа калорифера, с шумом)
- `cooler_temp`: FLOAT (Температура испарителя охладителя, с шумом)
- `target_temp`: FLOAT (Текущая уставка целевой температуры)
- `heater_power`: FLOAT (Выходная мощность нагревателя, 0..100%)
- `cooler_power`: FLOAT (Выходная мощность охладителя, 0..100%)
- `airflow_power`: FLOAT (Выходная мощность вентиляции, 0..100%)
- `dampers_open`: BOOLEAN (Состояние заслонок D)
- `is_manual_mode`: BOOLEAN (Флаг ручного режима)
- `current_state`: VARCHAR(30) (Текущее состояние FSM автомата)
- `t_pre_start`: FLOAT (Текущее расчетное время предпуска в минутах)

### Таблица `work_shifts` (График смен)

- `id`: INTEGER (PK, Autoincrement)
- `start_time`: VARCHAR(5) (Начало смены, формат `ЧЧ:ММ`)
- `end_time`: VARCHAR(5) (Окончание смены, формат `ЧЧ:ММ`)
- `target_temp`: FLOAT (Целевая комфортная уставка на смену, °C)
